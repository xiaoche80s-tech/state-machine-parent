## Context

当前执行快照时间线位于实例详情对话框（index.html 第 332-449 行）和侧边抽屉（第 452-572 行）中。每个快照项包含：
- 状态标记（圆形图标，SUCCESS 绿色/FAILED 红色）
- 状态名称 + 时间
- IN/OUT JSON 块（默认展开，占据大量空间）
- 错误信息（仅在 FAILED 时显示在底部）
- ROUTE 类型快照使用全宽紫色背景高亮，导致时间线连接线断裂

技术栈：Vue 3 (Composition API) + 纯 CSS，无构建工具，直接浏览器加载。

## Goals / Non-Goals

**Goals:**
- 减少单条快照的默认视觉占用，提升长流程实例的可浏览性
- 统一 ROUTE 和 NODE 类型快照的视觉层级
- 让错误信息在第一时间可见
- 保持时间线连接线的视觉连贯性

**Non-Goals:**
- 不改变后端数据模型或 API
- 不增加新的交互功能（如搜索/过滤快照）
- 不改变 Mermaid 流程图的渲染逻辑

## Decisions

### Decision 1: IN/OUT 块默认折叠，摘要行替代

**选择**：每个 IN/OUT 块默认只显示一行摘要（如 `IN: 3 fields, 1 nested`），右侧保留展开/折叠切换按钮。点击后展开完整 JSON（保持现有的预览/复制按钮）。

**备选方案**：
- 始终展示截断 JSON（当前方案）→ 视觉噪音大，用户需要滚动才能看到完整内容
- 完全移除摘要行，只显示"IN/OUT"标签 → 信息量不足，用户不知道展开后是什么

**理由**：折叠模式让用户快速浏览整个流程，只在需要时展开查看详情。摘要行提供足够的上下文判断是否需要展开。

### Decision 2: ROUTE 快照改为行内紧凑展示，不再使用全宽背景

**选择**：ROUTE 快照不再使用 `background: var(--primary-bg)` 全宽高亮，改为与 NODE 快照相同的结构：左侧标记点 + 右侧内容。标记点使用箭头图标（→），内容区显示 `stateName → target`。

**备选方案**：
- 保持全宽高亮但修复连接线 → 视觉上仍然突兀，与整体设计风格不统一
- 将 ROUTE 快照独立为单独区域 → 增加复杂度

**理由**：行内紧凑展示保持时间线的视觉节奏一致，连接线不会断裂。箭头标记点已能清楚区分 ROUTE 类型。

### Decision 3: 错误信息前置到 header 区域

**选择**：FAILED 状态的快照在 header 行下方直接显示错误信息（红色文字 + 红色左边框），不再放在 IO 块之后。这样用户无需滚动即可看到失败原因。

**备选方案**：
- 保持当前位置 → 用户需要滚动才能看到错误
- 在 header 中使用 tooltip 显示 → 交互成本过高

**理由**：错误信息是调试时最重要的信息，应当第一时间可见。红色左边框在视觉上与 header 建立关联。

### Decision 4: 简化 IN/OUT 块头部按钮

**选择**：将"预览"和"复制"按钮改为行内小图标（👁 和 📋），减少视觉噪音。

**备选方案**：
- 移除按钮，改为 hover 显示 → 移动端体验差
- 保持文字按钮 → 占用空间大

**理由**：图标按钮在有限的水平空间内提供相同功能，且视觉上更轻量。

## Risks / Trade-offs

- **[风险] 折叠状态增加交互步骤**：用户需要额外点击才能查看 JSON 内容。→ **缓解**：摘要行提供足够上下文，大多数浏览场景不需要展开。
- **[风险] 图标可访问性**：图标按钮不如文字按钮直观。→ **缓解**：添加 `title` 属性提供 tooltip 说明。
- **[权衡] 不改变数据模型**：如果未来需要更多快照元数据（如执行时长），需要后端配合。当前设计保持前端独立演进。
